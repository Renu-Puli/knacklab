1. ARCHITECTURAL IMPLEMENTATION OVERVIEW
--------------------------------------------------------------------------------
A. Hot Path Redirect Decoupling (apps/api/app/routers/redirect.py):
   - Fast Redirect Hot Path:
     Public short link redirects (GET /r/{code}) resolve target destinations via Redis cache
     (falling back to PostgreSQL on miss) and return HTTP 307 Temporary Redirect immediately.
   - Non-blocking Asynchronous Dispatch:
     Click event persistence is completely removed from the redirect response path.
     A lightweight event payload is dispatched to Celery/Redis via record_click_event_task.delay(payload).
   - Correlation ID & Stable Click Identifiers:
     Each event generates a deterministic idempotency key using the correlation Request ID:
     click_event_id = f"click_{request_id}".
   - Privacy Protection (Zero Raw IP Persistence):
     extract_ip_hash() hashes client IP via SHA-256. Raw client IP is never included in the queue
     payload and is never written to PostgreSQL.
   - Queue-Down Resilience & Best-Effort Degradation:
     Task dispatch is wrapped in try...except Exception. If the Redis broker or Celery worker
     is unreachable, a structured warning is logged and the redirect still succeeds immediately
     with HTTP 307. Public traffic is never degraded by analytics queue outages.

B. Celery App & Background Worker (apps/api/app/celery_app.py & app/worker.py):
   - Celery Application:
     Configured with Redis broker (redis://localhost:6379/0), task_serializer="json",
     timezone="UTC", task_acks_late=True, and task_reject_on_worker_lost=True.
   - Idempotent Click Event Recording (record_click_event_task):
     Consumes click payloads and inserts into PostgreSQL using:
     INSERT INTO click_events (...) ON CONFLICT (click_event_id) DO NOTHING RETURNING id;
     Guarantees that re-delivered or retried tasks cleanly deduplicate without raising exceptions
     or incrementing click counts.
   - Error Handling & Retries:
     Configured with max_retries=3 and exponential/fixed backoff for transient DB connection drops.
   - Retention Cleanup Task (purge_expired_clicks_task):
     Executes configurable retention cleanup (default 30 days):
     DELETE FROM click_events WHERE clicked_at < (now - retention_days);
     Purges expired analytical data in an atomic transaction while keeping parent links and
     recent click events intact.

C. Additive Database Schema & Alembic Migration:
   - Migration: apps/api/migrations/versions/a1b2c3d4e5f6_add_click_event_id_to_click_events.py
   - Schema Changes:
     ALTER TABLE click_events ADD COLUMN IF NOT EXISTS click_event_id VARCHAR(64) UNIQUE;
     CREATE INDEX IF NOT EXISTS ix_click_events_click_event_id ON click_events(click_event_id);
   - Preserved all historical click_events (360 existing rows) and all existing link records.

D. Protected Owner-Scoped Analytics Endpoint (apps/api/app/routers/links.py):
   - Route: GET /links/{id}/analytics
   - Authentication & Tenant Scoping:
     Requires valid API key (require_api_key). Validates link ownership (link.created_by == principal.org_id).
     Cross-tenant access returns HTTP 404 Not Found to prevent link ID enumeration.
   - Date Range Filtering & Validation:
     Supports ?from=YYYY-MM-DD&to=YYYY-MM-DD (defaults to past 30 days).
     Validates ISO date format and ensures from <= to (returns HTTP 400 Bad Request on invalid input).
   - Metrics Aggregation:
     Returns schema: {"link_id": int, "from": str, "to": str, "total_clicks": int, "last_clicked_at": Optional[str]}.
