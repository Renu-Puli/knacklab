1. ROOT CAUSE
--------------------------------------------------------------------------------
During STEP 5 (BREAK, Medium difficulty), cache invalidation in `apps/api/app/routers/links.py`
was bypassed inside `update_link()`:
The call `await invalidate_redirect_target(link.code, org_id=effective_org)` was commented out.

Consequently:
- Sending `PATCH /links/{id}` committed updated destination URLs to PostgreSQL.
- However, Redis retained the stale cache entry under key `link:{code}` with TTL up to 3,600s.
- Public redirect requests `GET /r/{code}` continued hitting Redis and serving the stale URL,
  violating read-after-write consistency until TTL expiration.

2. ARCHITECTURAL IDENTIFIERS & PROTOCOL
--------------------------------------------------------------------------------
- Where Cache Keys Are Computed:
  In `apps/api/app/cache.py`, via the helper function:
  `get_redirect_cache_key(code: str) -> str` which produces `f"link:{code}"`.
  The cached JSON value stores:
  `{"long_url": ..., "org_id": ..., "link_id": ..., "expires_at": ..., "cached_at": ...}`.

- Where Invalidation Should Happen:
  In `apps/api/app/routers/links.py`:
  a) Inside `update_link()`: immediately following successful database commit and refresh:
     `db.commit()`
     `db.refresh(link)`
     `await invalidate_redirect_target(link.code, org_id=effective_org)`
  b) Inside `delete_link()`: immediately following record deletion:
     `db.delete(link)`
     `db.commit()`
     `await invalidate_redirect_target(code_to_invalidate, org_id=effective_org)`

- What TTL Should Be:
  In `apps/api/app/cache.py`:
  - Default TTL: 3,600 seconds (1 hour).
  - Dynamic TTL Cap: If a link has a designated expiration date (`expires_at`), the TTL is
    dynamically computed as `min(3600, int((expires_at - now).total_seconds()))`.
    If already expired, the cache entry is rejected/evicted immediately and not populated.

3. CODE CHANGE & FIX APPLIED
--------------------------------------------------------------------------------
In `apps/api/app/routers/links.py`, inside `update_link()`:
Restored the exact invalidation call after database commit and refresh:
